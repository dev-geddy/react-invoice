## File map
Two droplet flavors: **pm2** (preferred — nvm node, nginx+certbot, db native or docker) and **docker** (apt node, Caddy, docker db). Setup + deploy come in matching pairs.
Multi-instance: several instances can share one droplet. Identity = `DOMAIN` (`-d`, required on setups + deploys — keys the deploy dir `/var/www/<domain>`) + `APP_NAME` (default `backflip` — pm2 process + nginx site `<name>.conf`) + `APP_PORT` (default 3070).
Blue/green layout under `/var/www/<domain>`: synced source at the root; two release slots `blue/` + `green/`; relative `current` symlink → live slot; `shared/` persistent (future admin file uploads — never wiped by deploys; each slot gets `shared -> ../shared` symlink). Deploy targets the INACTIVE slot (read `readlink current`; missing/foreign → blue), wipes+rebuilds it, flips `current` only after `slot/apps/web/server.js` exists → any failure before the flip leaves the live slot serving. `devops/rollback-for-pm2.sh -h -i -d [-n --app-port]` flips back to the other slot (refuses if empty); code-only — migrations not reverted.
Scripts are thin orchestrators over `devops/lib/remote/*.sh` fragments (standalone `set -euo pipefail` bash, piped via `remote_script <name> "VARS"` from common.sh; params via env prefix). Shared fragments: base-provision, hardening (single copy for both flavors now), node-nvm/node-apt, docker-engine, caddy(+render), nginx-install/nginx-certbot, firewall (HTTP3 toggle), app-dirs, db-ready/db-docker-up, app-release (parameterized NEEDS_NVM), slot-switch, artifact-extract/slot-activate (build-locally deploy), health-pm2/health-http. `pm2 startOrRestart --only <name>` + name-scoped health check → other apps untouched; one shared pm2 daemon (user `backflip`) supervises all. `devops/pm2/ecosystem.config.cjs` + `start.sh` are env-driven (`APP_NAME`/`APP_DIR`/`APP_PORT`). Docker flavor caveat: Caddyfile render is global single-site — multi-instance is a pm2-flavor feature.
Privilege model (both flavors): locked `backflip` app user (`APP_USER` in `lib/common.sh`; useradd -m, no password/ssh) owns `/var/www/<domain>` and runs pm2 + app (`pm2-backflip` systemd unit). Root does system work only (packages, db service/compose, nginx/Caddy, ufw). Deploy: rsync as root, then post-sync `chown -R backflip` (macOS rsync lacks `--chown`); app phase via `sudo -H -u backflip`; env files chowned on upload. pm2 flavor: nvm lives in `/home/backflip/.nvm`; remote app steps source it (non-interactive ssh has no profile); `pm2 startup` run by root with nvm bin on PATH so the unit finds node.
- `devops/setup-droplet-for-pm2.sh` — one-time provision, pm2 flavor. Flags `-h -i -d <domain> [-m <certbot-email>] [-u -p]`. apt base pkgs, 2G swap (if none — Next build OOM guard), nvm v0.40.3 → node 24 (`nvm alias default 24`) + corepack (yarn 4 via repo `packageManager` pin), pm2 (npm -g under nvm; systemd startup unit generated with nvm bin on PATH), nginx + certbot, ufw (OpenSSH/80/443 tcp), hardening (shared block, see below), app dirs. nginx site rendered locally from `devops/nginx/backflip.conf` (`__DOMAIN__`) → pushed to `/etc/nginx/sites-available/backflip.conf`, default site removed, `nginx -t` before reload. certbot: skipped if cert dir exists; `-m` email or `--register-unsafely-without-email`; failure (DNS not ready) = warn + continue, prints re-run command. No Docker. Satisfies `L2-DEVOPS-01`.
- `devops/setup-droplet-for-docker.sh` — one-time provision, docker flavor (former `setup-droplet.sh`): Docker via get.docker.com (db only), Node 24 (NodeSource) + corepack, pm2, native Caddy (official apt repo), ufw (OpenSSH/80/443 tcp+udp), same hardening block, app dirs. Satisfies `L2-DEVOPS-01`.
  - Hardening (both flavors): sshd drop-in `/etc/ssh/sshd_config.d/99-backflip-hardening.conf` (PasswordAuthentication no, KbdInteractiveAuthentication no, PermitRootLogin prohibit-password, X11Forwarding no, MaxAuthTries 4; `sshd -t` before `systemctl reload ssh`); fail2ban sshd jail via `/etc/fail2ban/jail.local` (`backend = systemd` — no rsyslog/auth.log dependency on minimal images; maxretry 5, bantime 1h, findtime 10m); unattended-upgrades via `/etc/apt/apt.conf.d/20auto-upgrades`.
- `devops/setup-droplet-db-native.sh` — db provision, native: PGDG apt repo → postgresql-17 (parity with compose/local 17), loopback-only assert, idempotent role+db create (`--db-name`/`--db-user` default `backflip`, `--db-password` generated + printed once if omitted; existing role's password never overwritten), prints `DATABASE_URL`. Satisfies `L2-DEVOPS-01`.
- `devops/setup-droplet-db-docker.sh` — db provision, docker: Docker engine + compose plugin only; db container starts on first deploy (needs droplet `.env`). Satisfies `L2-DEVOPS-01`.
- `devops/deploy-for-docker.sh` — deploy, docker flavor (former `deploy.sh`). Flags `-h -i [-u -p] [--env] [--env-local] [--skip-migrations]`. Flow: preflight ssh → optional env upload (0600) → verify droplet env → `sync_repo` → remote: `yarn install --immutable`, db up + health wait (60s), `yarn workspace web build`, `yarn db:migrate` (host → loopback db), copy standalone bundle → `/var/www/<domain>/releases/<utc-ts>`, flip base-level `current` symlink, `pm2 startOrRestart` + save, render Caddyfile (`__DOMAIN__` ← `.env`) + reload, prune to last 3 releases → health check (pm2 online + any HTTP code on :80). Satisfies `L2-DEVOPS-02`, `L2-DEVOPS-07`, `L2-DEVOPS-12`, `L2-DEVOPS-15`.
- `devops/deploy-for-pm2.sh` — deploy, pm2 flavor. Same flags/flow, with: remote steps source `$HOME/.nvm/nvm.sh` (non-interactive ssh has no profile — pm2/corepack live under nvm); db step branches — `systemctl is-active postgresql` → native (`pg_isready` on `127.0.0.1:$POSTGRES_PORT`), else docker present → compose up + health wait, else die with hint to db setup scripts; no proxy step (nginx+TLS owned by setup). Satisfies `L2-DEVOPS-02`, `L2-DEVOPS-07`, `L2-DEVOPS-12`, `L2-DEVOPS-15`.
- `devops/deploy-for-pm2-build-locally.sh` — deploy, pm2 flavor, **build on the operator's machine**. Same flags as `deploy-for-pm2.sh`. Flow: preflight ssh + app-dirs + optional env upload + verify droplet env → local `node_modules` required (dies with `corepack yarn install` hint) → local `yarn workspace web typecheck` → local `NEXT_SKIP_TYPECHECK=1 yarn workspace web build` → assemble artifact in `mktemp -d` (standalone bundle wholesale + `.next/static` + `public/` if present + `devops/pm2/`; `COPYFILE_DISABLE=1 tar -czf`) → cross-platform guard (any `*.node`/`*.dylib`/`*.dll` outside `node_modules/{@img,sharp}` → die with hint to `deploy-for-pm2.sh`; sharp itself only warns) → scp to `/tmp/<app>-artifact-$$.tgz` → `artifact-extract.sh` (root) → migrations via ssh tunnel (see below) → `slot-activate.sh` (app user, flip + pm2) → health check. No rsync, no remote install/build; ~13M artifact today. Satisfies `L2-DEVOPS-02`, `L2-DEVOPS-07`, `L2-DEVOPS-12`, `L2-DEVOPS-15`, `L2-DEVOPS-16`.
  - `lib/remote/artifact-extract.sh` (env `REMOTE_DIR APP_USER ARTIFACT`, root) — picks the inactive slot (same pure rule as `app-release.sh`: `readlink current`, missing/foreign → blue), wipes it, untars the artifact into it, `shared -> ../shared`, verifies `apps/web/server.js`, refreshes `$REMOTE_DIR/devops/pm2/` **from the artifact** (this flow syncs no source, and pm2 needs the ecosystem + start.sh there), `chown -R backflip`, deletes the tgz. Never flips `current`.
  - `lib/remote/slot-activate.sh` (env `REMOTE_DIR APP_NAME APP_PORT NEEDS_NVM`, app user) — recomputes the same target slot, verifies its `server.js`, flips `current`, `pm2 startOrRestart --only` + save. Like `slot-switch.sh` but tolerates a missing `current` (first deploy → blue); it is the go-live moment.
- `devops/deploy-for-pm2-build-docker.sh` — deploy, pm2 flavor, **build in a droplet-like container**. Third member of the family; strictly additive, changes no existing script. Same flags as `deploy-for-pm2-build-locally.sh` plus `--platform <p>` (default `linux/amd64`), `--build-only` (build + verify + print path/size, touch no remote host) and `--no-cache` (cold build, for measuring). Flow: docker/buildx/daemon preflight → emulation notice → ssh preflight + app-dirs + optional env upload + verify droplet env (skipped entirely under `--build-only`) → **native** `yarn workspace web typecheck` → `docker buildx build --platform … --target artifact --output type=local` → artifact lands at `.artifacts/<app-name>-artifact.tgz` (gitignored, one fixed name so runs don't pile up) → unpack + verify → scp → `artifact-extract.sh` → tunnel migrations → `slot-activate.sh` → health check. Everything from the upload onward is byte-identical to the build-locally flow, so blue/green, rollback and the `current`-flip guarantees are the same. Migrations still need local `node_modules` (checked in preflight unless `--skip-migrations`/`--build-only`). Satisfies `L2-DEVOPS-02`, `L2-DEVOPS-07`, `L2-DEVOPS-12`, `L2-DEVOPS-15`, `L2-DEVOPS-16` and its own `L2-DEVOPS-27`.
  - `devops/Dockerfile.build-artifact` — build-only image, never runs in prod. `node:24-bookworm-slim` (glibc 2.36 < Ubuntu 24.04's 2.39 → anything linked here loads there; the reverse would not), Node 24 matching the droplet's nvm 24, same image the Drone runner uses. Deliberately NOT `apps/web/Dockerfile`: that one is alpine/musl and produces a runnable image, and it provisions production so it must not change. Stages: `manifests` (harvest every `package.json` + `yarn.lock` + `.yarnrc.yml` with `find`/`install -D` — beats listing workspaces by hand, which silently rots when a package is added) → `deps` (`COPY --from=manifests`, whose cache key is the copied CONTENT, so a source-only edit leaves `yarn install --immutable` cached) → `build` → `assemble` (same layout `app-release.sh` builds and `artifact-extract.sh` untars: standalone wholesale + `.next/static` + `public/` + `devops/pm2/`; GNU tar, so no macOS AppleDouble/xattr noise) → `artifact` (`FROM scratch`, holds only `/artifact.tgz`, so `--output type=local` drops exactly one file on the host).
  - `devops/Dockerfile.build-artifact.dockerignore` — sidecar ignore file. BuildKit prefers `<dockerfile>.dockerignore` over the root `.dockerignore`, which lets this build have stricter rules without touching the root file that `apps/web/Dockerfile` + compose depend on. Needed: the root `.dockerignore` misses `apps/web/.next-e2e` (509M) and the local `.next` (2.1G). With the sidecar the context is ~2.5M.
  - Cache design (an emulated build is worth keeping warm): two **named** BuildKit cache mounts, `id=backflip-yarn-cache` → `/repo/.yarn/cache` (`.yarnrc.yml` sets `enableGlobalCache:false`, so yarn caches per-project) and `id=backflip-next-cache` → `/repo/apps/web/.next/cache` (turbopack persistent fs cache, `experimental.turbopackFileSystemCacheForBuild`). They persist across builds without being baked into layers, so even a source change gets an incremental compile.
  - Native-binary guard — **inverted** relative to `deploy-for-pm2-build-locally.sh`. That script tolerates the operator's own binaries and only warns about Darwin sharp; this one asserts the artifact matches the droplet and dies otherwise. `bin_kind()` classifies by magic bytes via `od` (no dependency on `file`, whose wording differs per platform): ELF `7f454c46` + `e_machine` at bytes 18-19 LE (`3e00` = x86-64, `b700` = aarch64), Mach-O `cffaedfe`/`cafebabe`, PE `4d5a`. Expected kind derives from `--platform`. Second, independent check for musl (droplet is glibc): `ld-musl` string inside the binary, or a `linuxmusl` path segment. Verified against real binaries — Darwin arm64 `.node`/`.dylib` → `Darwin/Mach-O`, aarch64 `/bin/ls` → `Linux/aarch64`, alpine busybox → passes the arch check but is caught by the musl probe.
  - Layout verification runs on every build (not just `--build-only`): `apps/web/server.js`, `apps/web/.next/static`, `devops/pm2/{ecosystem.config.cjs,start.sh}`, root `node_modules` — the exact set `artifact-extract.sh` + `slot-activate.sh` assert remotely, checked here where failure is cheap.
- `devops/nginx/backflip.conf` — nginx site template: `__DOMAIN__`, proxy → `127.0.0.1:3070`, websocket upgrade headers; `server_tokens off`; `access_log … backflip_scrubbed`; an exact-match `location = /api/auth/callback/credentials` with `limit_req zone=backflip_auth burst=10 nodelay` (→ 429); certbot injects TLS listener + redirect. Satisfies `L2-DEVOPS-05`, `L2-DEVOPS-22`, `L2-DEVOPS-23`.
- `devops/nginx/backflip-http.conf` — host-wide http-context snippet pushed to `/etc/nginx/conf.d/` by the pm2 setup (verbatim, not templated; shared by all instances, loaded before sites so references resolve at `nginx -t`): `limit_req_zone backflip_auth` (10r/m per IP), a `map` redacting `token=` query strings, and `log_format backflip_scrubbed`. Satisfies `L2-DEVOPS-22`, `L2-DEVOPS-23`.
- `.github/workflows/deploy.yml` — `workflow_dispatch` deploy (`L2-DEVOPS-08`); `permissions: contents: read`; deploy secrets passed via step `env:` and referenced as `"$VAR"` (never `${{ secrets.* }}` in `run:` text) → no shell-injection surface. Satisfies `L2-DEVOPS-24`.
- `devops/lib/common.sh` — sourced helpers: `log/ok/warn/die`, `remote_run` (ssh BatchMode + accept-new), `remote_copy` (scp), `sync_repo` (rsync `--delete`, excludes `.git node_modules .next .turbo .env* *.pem env*.deploy` + anchored `/releases` `/current`; guards on `REMOTE_DIR` set). Satisfies `L2-DEVOPS-03`.
- `devops/compose.prod.yml` — db-only (postgres:17-alpine, loopback `127.0.0.1:${POSTGRES_PORT:-5432}`, volume `backflip_pgdata`, healthcheck). Satisfies `L2-DEVOPS-04`.

- `devops/pm2/ecosystem.config.cjs` + `devops/pm2/start.sh` — pm2 app `backflip`: start.sh sources `/var/www/<domain>/.env{,.local}`, exports `PORT=3070 HOSTNAME=127.0.0.1`, execs `node /var/www/<domain>/current/apps/web/server.js`. Satisfies `L2-DEVOPS-15`.
- `devops/env/production.env.example` → droplet `.env` (POSTGRES_*, `DATABASE_URL` → 127.0.0.1, ENCRYPTION_KEY, DOMAIN). `production.env.local.example` → droplet `.env.local` (AUTH_*). Satisfies `L2-DEVOPS-06`, `L2-DEVOPS-11`.
- `apps/web/next.config.ts` — `output: "standalone"` + `outputFileTracingRoot` = repo root (bundle mirrors monorepo, server at `apps/web/server.js`). Satisfies `L2-DEVOPS-16` (owning tag lives with `L2-UI-10` config). Also exports `async headers()` applying `SECURITY_HEADERS` to `/:path*` (`L2-DEVOPS-21`): `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera/mic/geo/topics off), a conservative CSP (`frame-ancestors 'none'; base-uri 'self'; object-src 'none'` — no `script-src`/`style-src`, which would need per-request nonces for Next's inline hydration; left as a follow-up), and prod-only HSTS (`max-age=63072000; includeSubDomains`, gated on `NODE_ENV==="production"` so localhost is never pinned to https). App-level so it holds under both proxies; nginx/Caddy (`L2-DEVOPS-05`) may still add their own.
- `.github/workflows/deploy.yml` / `.drone.yml` — thin wrappers → `deploy-for-pm2-build-locally.sh` (matches the current droplet's pm2 flavor): runner installs deps (`corepack yarn install --immutable` — the script refuses without local node_modules) then typecheck/build/pack/tunnel-migrate run inside the script unchanged. Runners are glibc on purpose (GH: `ubuntu-latest` + setup-node 24 + yarn cache; Drone: `node:24-bookworm-slim` + apt bash/openssh-client for scp + ControlMaster tunnel) — the artifact's traced node_modules must match the droplet's Ubuntu; alpine/musl would ship wrong sharp binaries, and the script's native-binary guard is skipped on Linux builders. Satisfy `L2-DEVOPS-08`, `L2-DEVOPS-09`.
- `.drone.yml` carries two pipelines. `ci` (`L2-DEVOPS-25`): `node:24-bookworm-slim`, `corepack yarn install --immutable` → `typecheck` → `lint`, on push + pull_request, no secrets. `deploy` (`L2-DEVOPS-09`): `event: [push, promote]` + `branch: master` — **push to master deploys production automatically**; promote re-runs it against an older master build. The local `deploy-for-pm2-build-locally.sh` is now the break-glass path (ship from a workstation without waiting on CI), not the routine one.
- Drone records **no build at all** when every pipeline in the file is filtered out by its trigger (hit live 2026-08-06 while `.drone.yml` was promote-only: both the GitHub webhook and `drone build create` produced nothing, so `drone build promote` had no build number to target). Only relevant now for branches/events neither pipeline matches — worth knowing before adding narrow triggers.
- On a master push `ci` and `deploy` run in parallel; `ci` does **not** gate `deploy`. Deliberate: `deploy` runs `preflight_typecheck` before it builds or contacts the droplet, so a type error can't ship, and lint is warnings-only today. Cross-pipeline `depends_on` was avoided because a filtered-out dependency (`ci` doesn't run on promote) makes dependent-pipeline behaviour version-dependent.
- Two master pushes in quick succession race — Drone has no `concurrency` group like the Actions workflow. Blue/green makes a lost race a stale-slot problem, not a broken site, but avoid stacking pushes.
- `deploy_env` / `deploy_env_local` secrets are set (2026-08-06), so **every** deploy rewrites the droplet's `.env` and `.env.local` from Drone. Droplet-side hand edits to those files will be clobbered — change the secret, not the file.

## How it hangs together
- App runs ON the host (pm2, fork mode, 1 instance); only Postgres is dockerized; Caddy native fronts 80/443 → 127.0.0.1:3070.
- Releases are immutable slot copies (`blue`/`green`); `current` symlink flip is the go-live moment. Everything before the flip (install/build/migrate) cannot affect the serving slot; rollback = `rollback-for-pm2.sh` (flips to the previous slot; only one prior release retained by design).
- Migrations on host: root `db:migrate` → drizzle-kit; `packages/db/src/load-env.ts` reads `/var/www/<domain>/.env` (repo root = `/var/www/<domain>`) → loopback `DATABASE_URL`.
- Migrations in the build-locally flow run **from the operator's machine** (the droplet has no deps installed and Postgres is loopback-only): read `DATABASE_URL` out of the droplet `.env`, parse `user:pass@host[:port]/rest` (rest keeps db name + any `?query`), open an ssh tunnel `127.0.0.1:<free 54329-54349> → 127.0.0.1:<db port>` using a ControlMaster socket (`-M -S <sock> -f -N -o ExitOnForwardFailure=yes`; teardown `ssh -S <sock> -O exit`, also in the EXIT trap), then `DATABASE_URL=postgres://…@127.0.0.1:<local> corepack yarn db:migrate`. The exported var wins over the local repo's `.env`: `load-env.ts` calls dotenv `config()` without `override`, and dotenv never overwrites an already-set key (verified). Migrations still run **before** the flip, so a failure leaves the live slot serving. `db-ready.sh` runs first so the docker-db flavor is up before the tunnel.
- Owner seed (one-off): scp `.env.init` → `/var/www/<domain>/.env.init`, `corepack yarn init-owner` on host, rm. No container gymnastics anymore.
- Build happens in the synced source tree; `.next` survives rsync (excluded+protected) → warm build cache between deploys. Turbopack persistent fs cache enabled (`experimental.turbopackFileSystemCacheForBuild`, lives in `.next/cache`) — first droplet build after enabling is cold, later ones skip most compilation.
- Droplet build skips the TypeScript pass (`NEXT_SKIP_TYPECHECK=1` → `typescript.ignoreBuildErrors`; ~60s saved on 1 vCPU). Deploy scripts run `yarn workspace web typecheck` locally as preflight (guarded on `node_modules` presence — thin CI wrappers skip it; CI should typecheck separately).
- CI = thin wrappers only; deploy logic exists once in `deploy.sh` (`L2-DEVOPS-03`).

## Deviations / notes
- Flavors must not mix on one droplet: nginx and Caddy both bind 80/443.
- `sudo -u backflip` keeps the invoking cwd (often `/root`) — inaccessible to backflip → node/pm2 spawns die with EACCES. Every `sudo -H -u backflip` invocation must `cd` first (scripts do; remember for ad-hoc ssh commands).
- pm2 `startOrRestart` never updates an existing app's **script path** — after a deploy-dir move the process kept executing the old entrypoint (hit live on the /opt→/var/www migration: `errored`, MODULE_NOT_FOUND on the old path). Fragments now compare `pm_exec_path` against `$REMOTE_DIR/devops/pm2/start.sh` and `pm2 delete` + start when they differ.
- Current droplet 137.184.106.241 = pm2 flavor + native Postgres 17, instance `backflip` @ 3070, domain `backflip.dev-geddy.com` (LE cert issued 2026-07-29, auto-renew timer on). Deploy dir `/var/www/backflip.dev-geddy.com` (migrated from `/opt/backflip` 2026-07-29).
- Base + hardening block intentionally duplicated between the two setup scripts (each stays single-file, runnable in one go); keep them in sync when editing.
- CI wrappers assume the pm2 droplet flavor (build-locally script). A docker-flavor droplet would need the wrapper line switched back to `deploy-for-docker.sh`.
- `sync_repo` doesn't support SSH key paths with spaces (rsync `-e` word-splitting).
- Build-locally deploys ship the build machine's traced `node_modules`. Today that includes `@img/sharp-darwin-arm64` + its libvips `.dylib` (~10M of the 13M tarball) — Next's optional image optimizer, pulled in transitively; nothing renders `next/image`, so it is inert and the script only warns. Once images are optimized (or any other native module lands), use `deploy-for-pm2-build-docker.sh` (container build, same speed class) or `deploy-for-pm2.sh` (droplet build) — otherwise the artifact carries the wrong binary.
- **Which of the three to use.** Speed is no longer the deciding factor between build-locally and build-docker; correctness is.
  - `deploy-for-pm2-build-locally.sh` — fastest, but the artifact carries the operator OS's native binaries. Safe only while every native module in the trace is inert (today: sharp).
  - `deploy-for-pm2-build-docker.sh` — artifact carries the droplet's own `Linux/x86-64` glibc binaries (verified: `@img/sharp-linux-x64` + `libvips-cpp.so`, interpreter `ld-linux-x86-64.so.2`). Costs ~5s wall on a warm no-op run and ~13s when source changed. **Correct default the moment any native module stops being inert.**
  - `deploy-for-pm2.sh` — builds on the droplet. Slowest (1-2 vCPU), needed only when the source tree itself must be on the droplet.
- Measured on the operator machine 2026-08-20 (Darwin/arm64 M-series, Docker Desktop 29.6.2, **Rosetta amd64 emulation ON**, warm local `.next`). Wall time, whole `--build-only`-equivalent flow incl. native typecheck + assemble + tar:

  | flow | cold | warm, source changed | warm, no change |
  |---|---|---|---|
  | docker `--build-only` (`linux/amd64`) | **46.6s** (yarn install 22.4s + next build 15.4s) | **12.8s** (next build 5.8s, compile 1.5s) | **5.2s** (all layers CACHED; ~4.8s of it is the native typecheck) |
  | native (typecheck + build + pack) | — | — | **7.7s** |
  | native `next build` alone | 8.7s (compile 6.3s, 583% cpu) | — | 2.7s (compile 0.67s) |

  So the container build is **~2x** the native build on the compile step (15.4s vs 8.7s cold; 5.8s vs 2.7s warm), not the 5-10x a QEMU-emulated build would cost. **That 2x is entirely down to Rosetta** (`UseVirtualizationFrameworkRosetta: true` in Docker Desktop settings) — with plain QEMU the gap would be far larger and the recommendation would flip. Artifact 14M (docker, linux-x64 sharp) vs 13M (native, darwin-arm64 sharp).
- Docker build context is ~2.5M and transfers in ~0.1s; a full cache-hit `docker buildx build` alone is ~0.4s. Anything written into the repo root between runs (a stray log file) busts the `COPY . /repo` layer and forces the Next build to re-run — keep scratch output under `.artifacts/` (gitignored *and* in the sidecar dockerignore).
- The container build sets `NEXT_SKIP_TYPECHECK=1`; the script typechecks **natively** first, so the TypeScript pass never runs under emulation. That is why a warm no-op docker run (5.2s) is dominated by typecheck, not by Docker.
- Build-locally deploys never rsync the source tree, so a droplet previously deployed the other way keeps a stale copy of it. Only `.env{,.local}`, `shared/`, the slots and `devops/pm2/` (refreshed from every artifact) matter at runtime; the two scripts share the layout and can be alternated on one instance.
- `rollback-for-pm2.sh` is pm2-flavour only: it hardcodes `NEEDS_NVM=yes`, so on a docker-flavour droplet (apt node, no nvm) the slot-switch fragment can't source nvm. There is no `rollback-for-docker.sh`; the docker guide documents `git checkout <ref>` + redeploy instead. Parameterising the flag (or a second thin wrapper) would close the gap — see TODO.
- pm2 fork-mode restart on deploy = brief blip (~1s); accepted, no blue-green.
- Health check accepts any HTTP status on :80 (Caddy 308 → https expected).
- SSH after setup = key-only; password + keyboard-interactive auth off. Keep the droplet key safe — recovery is DO web console.
- Local full-docker path (`docker compose up --build`) now also runs the standalone bundle (see infra L3).
